# Implementation roadmap

**Status:** PROPOSED sequencing; dates and estimates are not commitments.

## Phase 0 — baseline and governance
Confirm repository ownership and whether a dedicated GitHub organization is required; verify branch protection; review Supabase security finding; verify Worker URL, domains, environments and logs; decide environment separation and recovery objectives.

**Exit:** reviewed baseline, assigned findings and no production changes.

## Phase 1 — engineering foundation
Choose framework after needs assessment; add manifest/lockfile, lint/type checks and CI; define environment-variable contract; create migration workflow and isolated test project; establish accessible UI shell and real loading/empty/error states.

## Phase 2 — portfolio core
Authentication/memberships, venture registry, lifecycle transitions, objectives, milestones, tasks, decisions, evidence, audit events and scoped access administration. Add authorization-negative tests.

## Phase 3 — operating visibility
Dashboard from real records, review cadence, risk/obligation register, document metadata, export and retention workflows.

## Phase 4 — finance and acquisition basics
Transactions, budgets, commitments, forecast assumptions, lead pipeline, follow-ups, experiments and conversion reporting; reconcile all totals.

## Phase 5 — integrations and intelligence
Accounting/email/storage adapters, AI summaries with provenance and approval, monitoring, usage/cost controls and abuse protections.

## Release gates
Code presence alone does not complete a phase. Require named tests, review evidence, staging validation, migration replay, security review and documented residual risks. Production release remains a separate approval.
